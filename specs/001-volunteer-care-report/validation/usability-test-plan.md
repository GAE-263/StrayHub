# 真人 Usability 測試計畫

**Feature**：志工日常照護回報與動物近期歷程  
**適用任務**：T253；測試結果由 T254、T255 分別記錄至志工與工作人員證據文件  
**建立日期**：2026-08-09  
**狀態**：固定測試 Protocol，尚未填入實際驗收結果

## 1. 目的與適用範圍

本計畫以固定腳本驗證下列成功條件：

- **SC-001**：未接受本系統專門訓練的志工，能獨立透過 LINE Bot 完成標準照護回報。
- **SC-002**：志工能在 90 秒內完成標準 LINE Bot 回報；計時不包含 AI 處理時間。
- **SC-006**：工作人員能在最多三次主要操作內進入指定動物歷程，並在兩秒內看到近 14 天主要摘要。
- **SC-014**：工作人員能正確區分「當日無回報」、「未觀察」、「無法判斷」與「AI 處理失敗」。

本測試只能驗證真人完成率、操作次數、時間與狀態辨識率；自動化 Integration／E2E Test、效能測試或測試主持人代操作不得取代真人結果。

## 2. 測試治理與安全原則

1. 所有測試只使用本機或受控 Demo 環境、虛構 Organization、虛構 Animal 與虛構回報資料。
2. 驗收證據不得保存 LINE User ID、真實姓名、電話、電子郵件、真實收容所名稱或正式收容所敏感資料。
3. 受測者使用去識別化代碼；測試主持人另行保存必要的聯絡與招募資料，不得放入本 Feature 證據文件。
4. 測試主持人必須使用本文件的固定說明，不得以提示、示範、代填或代操作提高完成率。
5. 失敗樣本、接受協助的樣本與中途退出的樣本都必須保留並計入結果，不得為了提高通過率刪除或替換。
6. 若發生環境或設備故障，原始紀錄仍保留；可在修復後重新安排測試，但不得覆寫原始失敗紀錄，且替代場次必須重新產生測試者代碼或明確標示為同一受測者的重測。

## 3. 受測者與樣本規則

| 角色     | 最低人數 | 代碼格式     | 必要條件                                            | 驗證範圍       |
| -------- | -------: | ------------ | --------------------------------------------------- | -------------- |
| 志工     |    10 人 | `V01`～`V10` | 未接受本系統專門訓練，且未參與本 Feature 設計或實作 | SC-001、SC-002 |
| 工作人員 |    10 人 | `S01`～`S10` | 未參與本 Feature 設計或實作；可使用管理介面         | SC-006、SC-014 |

- 每位受測者應使用相同版本的腳本、相同的虛構資料與相同的任務說明。
- 若實際招募超過 10 人，所有有效樣本與失敗樣本都納入計算，不只選取表現較好的 10 人。
- 「獨立完成」表示受測者沒有接受會改變操作路徑或答案的協助；設備連線、登入或環境重置等純技術協助仍須記錄。
- 受測者不得在正式測試前接受本系統操作教學；主持人只能朗讀固定任務說明與必要的隱私告知。

## 4. 測試環境與固定資料

### 4.1 環境

- 優先使用本機 MVP 環境；也可使用只含虛構資料的受控 Demo。
- 志工測試使用 Mock LINE／LIFF 或受控 LINE 測試入口；工作人員測試使用管理介面與既定 Timeline 路徑。
- 測試前重置登入狀態、Draft、暫存媒體與測試事件，避免前一位受測者的資料影響下一位。
- 測試主持人於每場記錄環境版本、裝置類型、瀏覽器或 LINE 測試入口，以及是否發生環境異常。

### 4.2 志工固定回報情境

每位志工使用同一隻虛構動物與同一份今日可回報資料。受測者必須完成動物確認及下列 13 個結構化題目；照片與心得不加入必要完成條件：

| 題目             | 固定測試答案     |
| ---------------- | ---------------- |
| 動物確認         | 明確確認指定動物 |
| 照護完成狀態     | 已完成照護       |
| 散步完成狀態     | 未進行散步       |
| 進食             | 正常進食         |
| 飲水             | 有觀察到飲水     |
| 活動             | 與平常相近       |
| 排尿             | 未觀察           |
| 排便             | 未觀察           |
| 護食或資源防衛   | 未觀察           |
| 對人的互動       | 與平常相近       |
| 對其他動物的互動 | 未觀察           |
| 情緒             | 平靜             |
| 散步反應         | 未進行散步       |
| 外觀／特殊狀態   | 未觀察           |

「散步完成狀態」與「散步反應」即使顯示相近文字，也必須由不同題目與不同類別保存；主持人不得代替系統判斷兩者是否混用。

### 4.3 工作人員固定 Timeline 情境

指定動物的近 14 日資料必須至少包含下列可辨識狀態，且資料皆為虛構：

| 日期相對位置 | 固定資料                   | 受測者應辨識的狀態 |
| ------------ | -------------------------- | ------------------ |
| 第 13 日前   | 一筆已保存回報             | 有回報             |
| 第 10 日前   | 沒有任何回報               | 當日無回報         |
| 第 7 日前    | 回報含「未觀察」答案       | 未觀察             |
| 第 4 日前    | 回報含「無法判斷」答案     | 無法判斷           |
| 第 2 日前    | 有原始回報，但 AI Job 失敗 | AI 處理失敗        |
| 第 1 日前    | 同日兩筆獨立回報           | 同日多筆均可查看   |

近 14 日的其他日期可使用一般虛構回報填補，但不得改變上述四種狀態的文字與語意。

## 5. 量測定義

### 5.1 志工計時

- **開始時間**：Bot 顯示第一個可操作的標準回報問題時開始；動物選擇與確認仍須完成，但不納入 SC-002 的 90 秒起算點。
- **結束時間**：系統顯示正式 Care Report 已保存成功時結束。
- **排除時間**：AI 處理、背景 Job、主持人記錄筆記與非受測者造成的環境修復時間不納入；所有排除原因仍要記錄。
- **90 秒通過**：從開始到結束的有效秒數小於或等於 90 秒，且 13 個結構化題目都有答案、摘要已確認並完成正式送出。

### 5.2 工作人員主要操作

一次主要操作是造成頁面、路由或主要內容面板切換的一次點擊或觸控。輸入搜尋文字、捲動與展開同一頁細節不另計一次主要操作。

- **操作起點**：受測者從管理介面固定起始頁開始尋找指定動物。
- **操作終點**：指定動物的 Timeline 主要摘要可見。
- **SC-006 時間**：使用工具或瀏覽器紀錄輔助記錄從 Timeline 主要內容請求開始到近 14 日摘要可見的時間；兩秒結果不得用主持人主觀估計取代。
- **SC-014 正確辨識**：受測者必須對四個固定情境逐一說出或選出正確狀態；任一狀態錯誤即不算該受測者的完整辨識通過。

## 6. 志工固定測試腳本（T254 使用）

### 6.1 主持人準備

1. 建立或重置本場受測者的虛構登入與 LINE Binding，確認只有指定 Organization 的 Active Shelter Context。
2. 確認指定動物出現在今日可回報範圍，並準備可從 Rich Menu 進入的「開始照護回報」與「今日照護毛孩」入口。
3. 確認 AI 處理可關閉或降級，避免 AI 完成與否影響人工回報保存。
4. 打開本場資料紀錄表，但不得讓受測者看到答案、通過門檻或其他人的結果。

### 6.2 朗讀給受測者的固定任務

> 請使用手機完成今天對指定動物的標準照護回報。請自行找到動物、確認動物，回答所有照護問題，確認摘要並送出回報。這次不需要拍照或留下心得。若你不確定某項觀察結果，請依你看到的選項作答。完成後請告訴我。

主持人只可在受測者要求時重複上述任務，不得告知按鈕位置、下一題答案、操作路徑或哪一個選項會通過。

### 6.3 執行步驟

1. 受測者從固定起始畫面進入 LINE Bot，透過今日名單、Rich Menu 或既定入口找到指定動物。
2. 受測者確認照片、名稱、完整收容編號與可用辨識資訊後，明確確認動物。
3. 第一個可操作問題出現時開始 SC-002 計時。
4. 受測者依序完成 13 個結構化題目；主持人只記錄答案與是否需要協助，不提示答案。
5. 受測者略過照片與心得，查看摘要並明確確認送出。
6. 系統顯示正式 Care Report 保存成功時停止計時；若受測者無法完成，記錄停止原因與當下狀態。
7. 測試結束後，主持人完成一列資料紀錄，不在受測者面前公布結果。

### 6.4 志工通過條件

受測者必須在沒有操作協助下完成動物確認、13 個結構化答案、摘要確認與正式送出，才記為 SC-001 的獨立完成；在 90 秒內完成上述條件才另外記為 SC-002 的時間通過。任一失敗都要保留紀錄，不能只記錄成功結果。

## 7. 工作人員固定測試腳本（T255 使用）

### 7.1 主持人準備

1. 建立或重置受測者的虛構 Staff 帳號，授權其查看指定 Organization 與指定動物。
2. 載入第 4.3 節的近 14 日 Timeline 固定資料，確認同日多筆、當日無回報、未觀察、無法判斷與 AI 處理失敗都可由畫面辨識。
3. 清除前一位受測者的搜尋、路由與 UI 狀態，讓每位受測者從同一管理起始頁開始。

### 7.2 朗讀給受測者的固定任務

> 請在管理介面找到指定動物，查看其近 14 日歷程。找到後，請告訴我哪一天沒有回報、哪一筆代表未觀察、哪一筆代表無法判斷，以及哪一筆的 AI 處理失敗。請依畫面內容回答，不需要修改任何資料。

主持人不得提示動物名稱、搜尋方式、Timeline 入口、日期或四種狀態的答案。

### 7.3 執行步驟

1. 受測者從固定管理起始頁開始；主持人開始記錄主要操作與時間。
2. 受測者自行找到指定動物並進入 Timeline。
3. Timeline 主要摘要可見時，記錄主要操作數與摘要顯示時間。
4. 受測者依序指出四種狀態及其對應資料；主持人逐項記錄答案，不提示正誤。
5. 受測者可展開同日兩筆回報，主持人確認兩筆均能個別查看，但展開同頁細節不另計主要操作。
6. 測試結束後，主持人完成一列資料紀錄，不在受測者面前公布結果。

### 7.4 工作人員通過條件

受測者在最多三次主要操作內進入指定動物 Timeline、兩秒內看到近 14 日主要摘要，且正確辨識四種固定狀態，才記為 SC-006／SC-014 的完整通過。若只有部分條件達成，必須分別記錄，不得合併為通過。

## 8. 每位受測者的資料紀錄欄位

每位受測者一列，至少記錄以下欄位；欄位內容不得包含直接識別個人或正式機構的資料：

| 欄位                 | 記錄規則                                                                 |
| -------------------- | ------------------------------------------------------------------------ |
| 測試批次             | 固定格式，例如 `2026-08-T253-01`                                         |
| 受測者代碼           | `V01`～`V10` 或 `S01`～`S10`                                             |
| 角色群組             | Volunteer 或 Staff                                                       |
| 裝置類型             | 只記手機／平板／桌面與作業系統類別，不記裝置序號                         |
| 測試環境             | Local 或 Controlled Demo 與版本識別                                      |
| 開始／結束時間       | 使用測試批次的時區與 ISO 8601 時間；不記個人日程資訊                     |
| 是否完成             | 是／否；失敗也必須保留該列                                               |
| 是否獨立完成         | 是／否／不適用；說明協助內容                                             |
| 是否接受協助         | 是／否；若是，記錄技術協助或操作提示類型                                 |
| 志工有效秒數         | 依第 5.1 節計算；非志工填寫不適用                                        |
| 工作人員主要操作次數 | 依第 5.2 節計算；非 Staff 填寫不適用                                     |
| Timeline 摘要秒數    | 使用工具紀錄；非 Staff 填寫不適用                                        |
| 四狀態辨識答案       | 逐項記錄正確／錯誤及受測者回答；不得只記總分                             |
| 失敗原因             | 從固定分類選取並補充描述：流程、理解、權限、網路、裝置、資料、系統或其他 |
| 最後操作狀態         | 例如 selecting、answering、reviewing、saved、timeline-visible            |
| 主持人備註           | 只記與測試相關的觀察，不記個人背景或敏感資料                             |

## 9. 統計與判定方式

1. **SC-001 完成率** = 獨立完成標準回報的人數 ÷ 全部已開始的志工樣本數；至少 10 人，至少 8 人通過。
2. **SC-002 時間通過率** = 在 90 秒內完成標準回報的人數 ÷ 全部已開始的志工樣本數；至少 10 人，至少 8 人通過。
3. **SC-006 操作與時間**：逐一檢查每位 Staff 是否最多三次主要操作、Timeline 摘要是否在兩秒內可見；至少 9 人同時達成兩項條件。
4. **SC-014 辨識率**：逐一檢查每位 Staff 是否正確辨識四種狀態；至少 9 人四項全對。
5. 若樣本超過 10 人，所有已開始的樣本都納入分母；不得排除失敗樣本或只計算完成者。
6. 自動化計時、瀏覽器紀錄或螢幕錄影只能作為證據輔助，不能代替獨立完成、操作理解或狀態辨識。

## 10. 失敗與重測處理

- 受測者答錯、找不到入口、超過時間、需要操作提示、未完成送出或無法辨識狀態，均是受測者結果，必須保留。
- 若發生資料載入錯誤、服務中斷、測試帳號設定錯誤或設備故障，須在失敗原因中標記為系統／環境因素，保留原始紀錄與錯誤時間。
- 環境修復後可安排重測，但重測不能刪除原始紀錄，也不能以重測結果覆蓋原始樣本；報告中須同時呈現首次測試與重測關係。
- 若固定資料、腳本或成功條件被修改，必須建立新測試批次，不得將不同版本結果混在同一批次。

## 11. 證據交付與隱私檢查

### T254 志工證據

將第 6 節腳本與第 8 節欄位的去識別化結果寫入 `validation/volunteer-usability-evidence.md`，並明確報告 SC-001 的獨立完成數、SC-002 的 90 秒內完成數、分母、失敗樣本與協助情形。

### T255 工作人員證據

將第 7 節腳本與第 8 節欄位的去識別化結果寫入 `validation/staff-usability-evidence.md`，並明確報告 SC-006 的三次操作／兩秒摘要結果、SC-014 的四狀態辨識結果、分母、失敗樣本與協助情形。

### 交付前檢查

- [ ] 沒有 LINE User ID、真實姓名、聯絡資訊或正式收容所敏感資料。
- [ ] 所有失敗、重測、接受協助與中途退出樣本都有保留。
- [ ] 每一筆結果都包含測試批次、受測者代碼、角色、裝置、時間、完成狀態與失敗原因欄位。
- [ ] SC-001／SC-002 的 13 個必填題目與照片／心得選填規則已在結果中可核對。
- [ ] SC-006／SC-014 的主要操作定義、兩秒摘要與四種狀態辨識結果已在結果中可核對。
