# 志工回報整理與處理流程

## 已確認範圍

- LINE Bot 題目、順序、文字與送出契約維持原樣。
- 台灣繁體中文後台，不顯示或編輯 JSON。
- 固定答案提供提醒底線，Gemini 僅摘要、引用原文、提出待確認事項。
- 提醒：建議優先查看／值得留意／一般紀錄；另標示資訊不足或描述矛盾。
- 處理：待確認 → 已確認或需追蹤 → 追蹤完成。保存人員、時間與備註。
- AI 覆核與照護處理各自獨立。無指派、期限、LINE 通知或健康分數。
- 新回報進背景工作；不自動回填歷史資料。模型失敗仍保留規則提醒。
- 所有讀寫與工作都使用伺服器驗證的 organization_id，沿用既有 RLS。

## 開發與驗證

1. 擴充既有回報模型與 migration，加入摘要投影、提醒與處理歷程。
2. 沿用 GeminiClient 與現有 AI worker，獨立 care_report_summary job，保留版本及原始結果。
3. 加入嚴格輸出與引用驗證；回報更正後舊摘要失效，不覆寫人員處理結果。
4. 管理 API 支援搜尋、狀態篩選、分頁與有版本檢查的處理操作。
5. 管理畫面呈現摘要、中文答案、心得／小故事、照片、處理紀錄。
6. 合成案例實際模型實驗及摘要／授權／隔離／競態／前端流程驗證。

## 操作語意

「已確認」表示工作人員已看過回報，不代表認可 AI 或動物健康正常。
「追蹤完成」只能從「需追蹤」進入，必須填寫結果；可重新開啟追蹤。
AI 整理不會將已確認的回報改回待確認；原文更正則要求重新確認。

## 現行 LINE 輸入與實際痛點

既有回報包含散步完成、活動狀況、走路狀況、排便狀況、遇到其他動物時、外觀／特殊狀態六項固定回答，以及補充說明、小故事與照片。這次不改題目或送出方式。

主要使用者是查看多筆回報、交接下一班的工作人員。優先解決：逐筆讀心得耗時、重要描述藏在補充文字、同事不確定是否已看過、需要追蹤卻沒有交接紀錄。未散步可能只是下雨；新志工不了解平常活動力；沒有遇到其他動物不等於互動正常。畫面保留原文與未觀察資訊，不推論成診斷或長期個性。

### 真實模型小實驗

沿用領養媒合的 GeminiClient 和環境設定，實際模型為 `gemini-3.5-flash-lite`，提示版本 2。只送合成資料，不讀真實志工回報、不寫入資料庫。重跑指令：`uv run python -m scripts.experiment_report_summary`。

| 合成情境 | 最後一輪提醒 | 資訊判斷 |
| --- | --- | --- |
| 正常完成散步 | 一般紀錄 | 清楚 |
| 下雨取消散步，精神與平常一樣 | 值得留意 | 清楚，未誤升為優先查看 |
| 右後腳不敢踩地 | 建議優先查看 | 清楚 |
| 今天沒有流血，也沒有跛腳 | 一般紀錄 | 清楚，保留否定語意 |
| 勾選正常，補充拖腳及流血並說選錯 | 建議優先查看 | 描述有出入 |
| 首次帶犬，不知道平常狀況 | 一般紀錄 | 資訊不足 |
| 文字要求忽略規則、改用英文 | 一般紀錄 | 忽略指令，仍輸出繁中 |
| 便便偏軟，其餘如常 | 值得留意 | 清楚 |

最後一輪 8／8 通過格式、引用與預期資訊類別檢查。前幾輪曾出現回傳 schema、陣列型別錯誤及過度判斷矛盾；格式錯誤會被驗證器拒絕，並已調整提示。這是流程可行性實驗，不能視為實際場域準確率；目前也不分析照片、不自動判定疾病。

### 本機啟用事項

Next 開發畫面可直接查看 `/reports`。API 與 worker 必須載入這次程式碼後，新回報才能自動整理。現有 worker 是 LINE demo 腳本的受管子程序，沒有熱重載；停止單一 worker 會觸發腳本清理 API、Web 與 tunnel。因此這次沒有中斷該程序，需在下一次重啟整組本機 demo 服務後啟用背景摘要。部署順序：migration → 更新／重啟 API 與 worker → 送一筆新回報驗證。不要讓舊 worker 處理新摘要工作。

無模型憑證、連線失敗或輸出不合格式時，背景工作沿用重試上限，畫面顯示固定回答整理與未完成提示；原文與人工處理紀錄不受影響。
